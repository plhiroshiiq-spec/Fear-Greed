# 終値ソースの選定記録(P4 / SL WATCH)

対象: SPEC.md 9.1章「終値の入手(0円の選択肢。P4で選定し `docs/price_source.md` に記録)」。

- **結論: (a) 引け後に手動で終値を入力する。(b) 無料の株価ソースの追加は保留。**
- 判断日: 2026-09-18
- 運用費: **0円**(SPEC.md 設計原則4)

---

## 1. 判断の理由

SPEC.md 9.1章は (b) について次の条件を置いている。

> **株式分割の調整が信用できないソースは使わない**。分割で新高値判定やSL距離が静かに壊れるため、
> 分割イベントの扱いを必ず確認すること。

**この条件を満たすことを確認できなかった。** したがって同章の

> 判断がつかない場合は(a)で実装し、(b)は保留する

に従う。「確認できなかったから、たぶん大丈夫だろう」で採用することは設計原則1
(壊れても嘘をつかない)に反する。

### 確認できなかった理由

P4 の作業環境は外向き通信がポリシーで制限されており、候補ソースに1件も到達できなかった。

| 候補 | 結果 |
|---|---|
| `stooq.com` | egress proxy が CONNECT に 403 |
| `query1.finance.yahoo.com`(Yahoo Finance の非公式エンドポイント) | 同上 |
| `www.jpx.co.jp` | 同上 |
| `kabutan.jp` | 同上 |

**注意**: これは「Android アプリからも使えない」という意味ではない。**開発環境の制約であって、
ソースの良し悪しの評価ではない。** 分割調整の挙動を実データで検証できなかった、という一点だけが
判断の根拠である。

### 到達できても採用を急がない理由

分割調整の検証は「繋がるか」ではなく「**分割日をまたいで過去の終値が遡及調整されるか**」を
見る作業になる。具体的には次を確認する必要がある。

1. 直近1年で分割した銘柄(例: 1:5 の株式分割)を1つ選ぶ
2. 分割日の**前日の終値**を取得する
3. その値が分割後の株価水準に合わせて割り戻されているか(遡及調整)、
   それとも分割前の生の値のままか(未調整)を見る
4. **未調整なら使わない。** SL距離が一夜で5倍に見え、割れ判定が静かに壊れる

この検証は実データが要るので、到達できるようになってから行う。

## 2. (a) 手動入力で足りる根拠

SPEC.md 9.1章の前提がそもそも手動入力と相性が良い。

- **判定は終値ベース**。ザラ場中のリアルタイム株価は取得しない(TradingView のアラートの役割)
- 判定は**引け後に1回**行い、翌朝まで表示する
- 建玉は数銘柄の想定(「1件20秒程度」で追加する運用)

つまり必要なのは **1日1回、保有銘柄ぶんの終値を入れるだけ**。5銘柄なら30秒程度で、
建玉の追加作業(1件20秒)と同じ桁の手間しかかからない。

**手動入力の利点**:

- 分割の取り違えが起きない(自分が見ている画面の値をそのまま入れる)
- 外部サービスの仕様変更・遮断で静かに壊れない
- 契約もAPIキーも不要

**手動入力の欠点**:

- 入れ忘れる日がある → 対策: 入力が無い建玉は**判定済みに数えない**。
  `SlWatch` は `unpriced` として別に数え、表示にも出す。
  割れ0件と未入力を混同させない(設計原則1)。

## 3. (b) に移る条件

次がすべて満たせたら (b) を再検討する。判断は本ファイルを更新して記録すること。

1. 候補ソースに到達でき、上の「分割調整の検証」4手順を実データで通せた
2. 無料枠のままで、APIキーも契約も不要である
3. 取得失敗時に**前回値を使い回さない**実装ができる(誤った終値で割れ判定を出さない)
4. 手動入力の経路は**残す**(ソースが落ちた日に運用が止まらないようにする)

3 が特に重要で、SL の判定は誤検知も見逃しも損失に直結する。株価ソースを足すのは
「手間を減らす」ためであって、「判定を不確かにする」ためではない。

## 4. 実装への反映

- `SlWatch` は終値を外から受け取るだけで、取得方法を知らない。
  (a) と (b) の差し替えが `ClosePriceSource` の実装差になるようにしてある。
- 終値が無い建玉は `unpriced` として数え、割れ0件と区別する。
- 表示には**判定に使った終値の日付を必ず添える**(9.1章)。
  日付が建玉ごとに違う場合は**最も古い日付**を出す(新しく見せない)。
